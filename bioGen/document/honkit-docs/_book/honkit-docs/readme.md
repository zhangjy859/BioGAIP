# Secure HonKit Documentation via Cloudflare Workers

This project hosts [HonKit](https://github.com/honkit/honkit) generated documentation using **Cloudflare Workers** and **Static Assets**. The site is protected by HTTP Basic Authentication and hosted on a custom domain.

## Project Structure

- `_book/`: The output directory generated by HonKit containing the static HTML files.
- `src/worker.ts`: The TypeScript Cloudflare Worker that intercepts requests and enforces password protection.
- `wrangler.jsonc`: The Cloudflare configuration file. It binds the static assets, enforces the worker to run first, and sets the custom domain.

## Prerequisites

1. Node.js installed.
2. Cloudflare account with a registered domain.
3. Cloudflare CLI (`wrangler`) authenticated locally (`npx wrangler login`).

## How to Build and Deploy

### 1. Build the Documentation
Before deploying, always ensure your HonKit documentation is built locally so the `_book` folder is up to date:

    npx honkit build

### 2. Configure Your Custom Domain
Open `wrangler.jsonc` and ensure your custom domain is correctly set in the `routes` array. 

*(Note: The base domain must already be active in your Cloudflare dashboard DNS settings).*

    "routes": [
      {
        "pattern": "docs.yourdomain.com",
        "custom_domain": true
      }
    ]

### 3. Set Up Production Secrets (Authentication)
The documentation is protected by a username and password. **Do not put these in the code.** They are securely stored in Cloudflare. 

If this is a **new deployment** or you want to **change the credentials**, run these commands in your terminal and type your desired values when prompted:

    npx wrangler secret put DOCS_USERNAME
    npx wrangler secret put DOCS_PASSWORD

### 4. Deploy to Cloudflare
Once the docs are built and secrets are set, publish the site using:

    npx wrangler deploy

## Local Development & Testing

If you want to test the Worker and documentation locally before deploying, you need to set up local environment variables.

1. Create a file named `.dev.vars` in the root of this project.
2. Add your test credentials:

    DOCS_USERNAME=admin
    DOCS_PASSWORD=local_password

3. Run the local development server:

    npx wrangler dev

*(Warning: Ensure `.dev.vars` is added to your `.gitignore` file so you do not commit secrets!)*

## Important Architecture Notes for Future Reference

- **Why run_worker_first: true?** 
  In `wrangler.jsonc`, under the `assets` object, `run_worker_first: true` is strictly required. Without it, Cloudflare will bypass `worker.ts` to serve the `_book` HTML files directly, which completely defeats the password protection.
- **The ASSETS Binding:** 
  The worker authenticates the user, and if successful, calls `env.ASSETS.fetch(request)`. This tells Cloudflare to grab the requested static file from the uploaded `_book` folder.
